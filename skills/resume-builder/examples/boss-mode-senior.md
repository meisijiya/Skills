# 资深案例:5 年经验怎么写酥神简历?

> 资深候选人的误区:经历太多,什么都想写,结果 HR 看不到重点。
> 酥神方法论的回答:**经历不是流水账,是「能力证明的合集」**。5 年经验,只留 3 个能打的项目。

---

## 原始素材

```
求职方向:资深后端 / 架构师
教育:XX 大学 软件工程 2016-2020
经历:
- 2018-2020 某创业公司 Java 开发(电商系统、后台管理)
- 2020-2022 某中厂 后端(订单系统、优惠券系统)
- 2022-2024 某大厂 后端(交易中台、风控系统)
- 2024-至今 某大厂 技术专家(架构组)
项目(数量多、杂):
- 电商后台、订单系统、优惠券、秒杀、风控、消息队列、分布式事务……
```

## 体检报告

| 军规 | 结果 | 说明 |
|------|------|------|
| 1 Owner | ⚠️ | 很多项目是「参与」,需要逐条筛选 |
| 2 0→1 | ⚠️ | 秒杀、风控可能是 0→1,需要确认 |
| 6 数据 | ❌ | 没有量化 |
| 7 岗位词 | ⚠️ | 有,但没对照目标岗位 |
| 8 分点 | ❌ | 项目太多太散 |

## 关键决策

1. **只留 3 个「能力证明」项目**:
   - 最能体现架构能力的(秒杀系统 0→1)
   - 最能体现业务价值的(交易中台支撑 XX 业务)
   - 最能体现影响力的(风控系统降低资损 XX 万)
2. **合并**:电商后台、订单系统等次要项目并入「主导 XX 系统群」一句话
3. **资深加分项(简历里必写)**:
   - 带团队:mentor 过 X 人
   - 技术影响力:内部技术分享、专利、开源
   - 业务影响力:直接挂钩 GMV/资损/成本
4. **数据要「大」**:资深级数据是「千万级 QPS」「亿级用户」「XX 万资损」,不是「+25%」

## 酥神改写结果

```
[ 某大厂 - 交易中台架构组 · 技术专家 ]    2022 - 至今

项目【0→1 秒杀系统(支撑 618 峰值)】
─ 背景与目标:0→1 搭建大促秒杀系统,支撑 618 峰值流量。
─ 我的职责:【项目 Owner】主导架构设计:缓存预加载、MQ 削峰、
  限流降级、库存一致性方案。
─ 技术细节:Redis 预扣库存 + MQ 异步落库;Sentinel 限流;
  多级缓存;压测 10w QPS 无抖动。
─ 数据指标:峰值 <span class="metric">10w QPS</span>,
  库存超卖 <span class="metric">0</span>,
  接口耗时 P99 <span class="metric">&lt; 50ms</span>。

项目【交易中台改造(支撑 3 个业务线接入)】
─ 我的职责:主导中台化改造,抽象交易核心链路。
─ 技术细节:领域驱动设计重构;统一交易引擎;分布式事务方案选型。
─ 数据指标:新业务接入周期从 <span class="metric">3 个月 → 2 周</span>,
  支撑 GMV <span class="metric">100 亿+/年</span>。

项目【风控系统(资损防控)】
─ 我的职责:主导风控策略引擎升级。
─ 技术细节:规则引擎 + 实时特征 + 模型打分分级处置。
─ 数据指标:年度拦截资损 <span class="metric">500 万+</span>,
  误伤率 <span class="metric">-30%</span>。

[ 影响力 ]
Mentor 5 名新人 · 内部技术分享 10+ 场 · 专利 2 项 · 开源项目 1 个
```

## 资深军规补充

1. **「带团队」是硬通货**:Mentor/带人/指导,是资深和初级的本质区别,必须写
2. **数据要大而准**:QPS、GMV、资损、P99——资深的数据必须「行业级」
3. **能力证明优先于经历罗列**:5 年写 3 个项目,比写 20 个「参与」强
4. **影响力要外显**:技术分享、专利、开源——这是「内部认可」的证明

## 金句

> 资深简历不是「我做过的所有事」,是「我能扛的所有事」。
> 每写一个项目,问自己:这个项目能证明我值这个价吗?不能,删。
