# 简历构建器(酥神 × GodSU 融合版)

把平淡的经历改写成让面试官「被镇住」的高信号简历,方法论融合自酥神(`IM-NOT-GOD-SU`)与 GodSU 两个公开简历方法论项目:酥神的 10 条军规 + 公司色块视觉系统 + GodSU 的 11 个手法 + 13 个句式 + 防伪审计。

**核心信念**:

> 简历不是自传,是广告。
> 所有「参与/协助/学习了」都是噪音。
> 所有「自我评价」都是废话,外部认可才是证据。
> 你写的每一个项目,HR 只关心三个字:你 owner 吗?

> 简历的最高境界:让 HR 看完第一屏,就忍不住翻第二屏。

---

## 何时使用

- 用户要求「帮我写/优化/包装/重写简历」「按酥神风格做简历」
- 用户给了经历素材(教育/实习/项目/获奖),需要一份成品简历
- 用户抱怨「简历投出去没有回音」「简历被筛掉了」→ 先体检再改写
- 用户说「做成酥神同款」「按我的参考图做」「过筛简历」
- 用户给出口头描述,需要转成简历 bullet
- 中英文简历均可

## 何时不使用

- 用户只要一个 HTML 模板文件本身(不做内容改写)→ 直接给 `assets/template.html`
- 用户只要一页纯文字简历(不渲染)→ 简化流程,只做 Step 1-3
- 闲聊/不产出文件

## 工作流(五步,必须按序执行)

### Step 1 · 挖料(先问,别急着写)

用户给的初始素材几乎总是不够的。简历写得弱,90% 是因为料没挖出来,不是文笔问题。对每段经历追问:

| 维度 | 追问示例 |
|------|---------|
| Ownership | 你负责到什么程度?owner / 核心成员 / 参与者?从 0 到 1 还是接手维护? |
| 数字 | 性能/成本/耗时/调用量/用户量/转化率/覆盖率/Star 数/榜单名次 |
| 对比 | 旧方案是什么,为什么不行,你改成了什么? |
| 锚点 | GitHub 链接、线上产品域名、开源社区身份、比赛名次、内部榜单 |
| 极值 | 最年轻的、第一个、排名第一的、唯一的 |
| 人味 | 跨界背景、非典型起点、反差素材 |

用户丢来现成简历时,**先逐条诊断**(用 [references/methodology.md](references/methodology.md) 里的检查表),标出每条缺什么,再挖料。

### Step 2 · 定信号(头部即胜负)

面试官平均 30 秒扫一份简历。前 5 行决定他用什么心态读剩下的部分。

- 把**最稀缺、最可验证**的 2-4 个信号压进姓名下方的一行简介里
- 经历排序按信号强度,**不必严格按时间**(最硬的一段放最前)
- 每个头部信号配可点击/可搜索的锚点(GitHub、线上产品、奖项链接)
- 头部标签 ≤ 3 个,最炸的给金色 `class="tag gold"`

### Step 3 · 改写(体检 + 四段式 + 句式)

**3a · 体检报告**(酥神 10 军规 gap 检测)

对每段经历逐条体检,产出结构化报告告诉用户缺什么。10 条军规完整版见 [references/methodology.md](references/methodology.md) §一。

**3b · 四段式改写**(酥神骨架 + GodSU 演进叙事)

```
项目名(+影响力徽章,如 ★ 7.6k)
─ 背景与目标:一句话抬出项目规模/业务价值,注明【0→1】
─ 我的职责:【项目 Owner】主导,0→1 搭建 XX 系统/平台/模块
─ 技术细节:密集使用岗位关键词,写架构/方案/路径/硬核方案,2-4 条
─ 数据指标:量化结果(通过率 +25% / 耗时缩短 A→B / 转化率),加粗显示
```

升级改写原则(完整见 [methodology.md](references/methodology.md) §二):
- 每段经历只留 2 个最能打的项目
- 删除所有自我评价词,全部替换为事实和证据
- 用户没指标,标 `【待补:XX指标】`,**严禁编造数据**
- GodSU 演进叙事句式:1.0 有什么问题 → 改成 2.0 → 收益

**3c · 句式套用**(GodSU 13 句式)

13 个可复用句式作为零件库,改写时逐条对照套用,完整见 [methodology.md](references/methodology.md) §三。

### Step 4 · 防伪审计(必做,不可跳过)

逐条过一遍成稿,对每个 claim 问 4 个问题:

1. **面试官追问 3 层,用户能守住吗?**("这个 25% 怎么测的?baseline 是什么?") 守不住 → 降级措辞或删掉
2. **数字的口径能说清吗?** 每个数字用户要能一句话说出来源
3. **热词用户能定义吗?** 让用户口头解释一遍他简历里的每个术语,卡壳的换成平实说法
4. **ownership 会不会被背调/交叉面试戳穿?** 团队项目把队友活写成自己的,是死法

把审计中降级/删除的条目告诉用户并说明原因——这本身就是给用户的面试预演。

### Step 5 · 排版与渲染

文案定稿后,产出可打印文件:

1. **填模板**:复制 `assets/template.html`(酥神 v3,带公司色块)或 `assets/template-pdf.html`(GodSU 一页 A4 PDF 风格),把 `{{占位符}}` 替换为按模板注释写的正文
2. **渲染**:macOS 用 `bash scripts/render.sh <input.html> <output.pdf>`(无头 Chrome)
3. **压一页**:超出一页时按顺序试:删弱条目 → 微调 padding(±1-2px) → 行高 1.6 → 1.5
4. **视觉验收**:PyMuPDF 渲染第一页 PNG 自查,确认色块+字号+分行正确

待确认项在 HTML 里用 `<span class="todo">` 黄色高亮标出,视觉上无处可藏,终稿必须清零。

## 输出格式

每次产出简历,按这个顺序输出:

1. **信息缺口清单**(Step 1 收料后):列出缺失字段,标注优先级(头衔/数据/外部认可优先级最高)
2. **体检报告**(Step 3a):按 10 军规逐条 ✅/❌/⚠️
3. **改写后简历正文**(Step 3b-3c,Markdown,保持用户语言)
4. **防伪审计结果**(Step 4):降级/删除的条目 + 原因
5. **HTML 成品 + PDF**(Step 5):`resume_{{姓名拼音}}.html` + `.pdf`

## 失败模式与 Fallback

| 场景 | 处理 |
|------|------|
| 用户没给目标岗位 | 默认按「AI 应用工程师 / 大模型方向」JD 关键词重写,并注明假设 |
| 用户经历只有「参与/协助」 | 追问具体职责;若无,合并进上级项目,标注「项目贡献者」而非「Owner」 |
| 用户没有数据指标 | 标 `【待补:XX指标】`,**不编数据**;提示「没有数据就没有军规 6」 |
| 用户经历与岗位无关 | 直接说「这段对目标岗位是噪音,建议删除」 |
| 用户想渲染但信息不完整 | 输出体检报告 + 半成品 HTML(`【待补】` 占位),让用户补完再渲染 |
| 用户要求编造数据/奖项 | **拒绝**,解释:包装被戳穿的负收益远大于平淡的负收益 |

## 诚实边界(可被引用为约束)

- **不编造**任何项目、公司、奖项、数据、身份、Star 数
- **不夸大**ownership ——「参与」若确实只是参与,标「项目贡献者」而非强行「Owner」
- 可以帮用户把「做过的事」用最强的措辞表达,**但绝不做假**
- 「酥神方法论」是一种简历包装方法的代称,不承诺任何 offer
