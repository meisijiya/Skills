# 反模式与防伪清单

> 简历「自杀」清单 —— 出现即删 / 出现即降级 / 出现即防伪。改写时对照检查。

---

## 一、酥神反例黑名单(出现即删,一条不留)

### 自我评价类

- 「学习能力强」「认真负责」「吃苦耐劳」「抗压能力强」「热爱技术」
- 「沟通能力强」「有团队精神」「积极主动」
- 任何形容词堆砌(「极大提升了」「显著优化了」)而没有数字

### 动词弱化类(参与→主导升级)

| ❌ 弱动词 | ✅ 强动词(前提:真实相符) |
|---|---|
| 参与了 | 【项目 Owner】主导 |
| 协助了 | 主导 / 负责 |
| 学习了 | 0→1 搭建 |
| 帮忙做了 | 设计并推动 |
| 负责了一些 | 负责 + 量化结果 |
| 深入了解 | 主导落地 |
| 熟练使用 | 设计并实现 |

### 凑数技术栈

- 「精通 Java、Python、Go、C++、React、Vue、MySQL、Redis」全家桶 = 凑数
- 列出但没有用过的语言/框架/工具
- 培训课程 + 证书堆砌(没有项目应用证据)

## 二、GodSU 防伪清单(出现即触发审计降级)

### 数字类

| 问题 | 风险 | 处理 |
|------|------|------|
| 精确到小数点(如「提升 23.7%」) | 现场被问「怎么测的?baseline 是什么?」可能答不出 | 改为「约 25%+」+ 注明口径 |
| 单条 bullet 罗列 4 个以上数据 | 任何一个被戳穿,其他连带失信 | 每条 bullet 1-2 个核心数据 |
| 没有基线的对比 | 面试官追问「和什么比」答不出 | 永远写明对照基线(「较全量重跑」「较上线前」) |
| 数据看起来过好(如「性能提升 10x」) | 一听就假 | 重新核实,做不到就降到「2x」「3x」 |

### 热词类

| 问题 | 风险 | 处理 |
|------|------|------|
| 用了热词但用户口头讲不清 | 面试官一问就卡壳 = 自爆 | 让用户口头过一遍每个术语,讲不清的换平实说法 |
| 映射了 4 个以上行业热词 | 怀疑简历是「概念拼装」不是真做 | 减到 1-2 个用户真正深度做过的 |
| 自造概念但行业无对应 | 面试官追问无据可查 | 换成行业已有提法(对齐 LangChain / Anthropic / Google 等) |

### Ownership 类

| 问题 | 风险 | 处理 |
|------|------|------|
| 团队项目写成「项目 Owner」 | 背调 / 交叉面试必穿 | 标「核心作者之一」「主导 X 到 Y 的升级」|
| 把 mentor/学长带的工作写成自己的 | 失信 + 行业小圈子会传 | 老实写「参与」,把亮点归到团队项目 |
| 实习期间打杂工作写「0→1 搭建」 | 上下文对不上 | 标「迭代维护」,突出改进的局部模块 |

## 三、防伪 4 问(每条 claim 都得过)

改写完成后,对每个 claim 逐条问:

1. **面试官追问 3 层,用户能守住吗?**
   - 「这个 25% 怎么测的?baseline 是什么?样本量多少?」
   - 守不住 → 降级措辞或删掉

2. **数字的口径能说清吗?**
   - 每个数字用户要能一句话说清来源(测试集名、时间窗口、对照对象)
   - 说不清 → 删或降级

3. **热词用户能定义吗?**
   - 让用户口头解释一遍他简历里的每个术语
   - 卡壳 → 换平实说法

4. **ownership 会不会被背调/交叉面试戳穿?**
   - 团队项目里把队友的活写成自己的,是最常见的死法
   - 戳穿风险高 → 诚实降级

## 四、简历「自杀」清单(其他常识错误)

- 简历标题写「我的简历.pdf」 / 文件名 `未命名文档(3).pdf`
- 自我评价 200 字小作文
- 错别字、标点中英混用(中文简历出现 full-width 逗号乱用)
- 照片模糊或证件照风格突兀
- 经历时间混乱(2025.05-2026.05 写错为 2025.5-2026.5)
- 联系方式缺失或写错(电话位数不对、邮箱拼写错)
- 一份简历投所有岗位(海投党标记)
- 实习时间 < 3 个月还在简历上硬撑(建议合并或删)
- 学校 / 公司名拼写错(致命的常识错误)

## 五、降级 vs 删除的判断树

```
claim 被质疑
├─ 用户能讲清口径 / 定义 / 细节? 
│   ├─ 是 → 保留(若可信度高,加强)
│   └─ 否 → 降级措辞
│       ├─ 降级后还是可疑?
│       │   ├─ 否 → 保留(降级版)
│       │   └─ 是 → 删除
│       └─ 降级后失去价值? → 删除
```

> 原则:**降级 + 保留 > 删除 + 替换填料**。降级是诚实的体现,删了再用模糊词填空反而更糟。
