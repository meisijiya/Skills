## 一、酥神 10 条军规(体检检查表)

每条军规的格式:**为什么** / **怎么用** / **反模式**。

### 军规 1 · 项目必须是 Owner

**为什么**:HR 和面试官筛简历时,第一眼找的是「你在这件事里到底是干嘛的」。「参与」「协助」在筛选系统眼里等于「打杂」,直接过滤。

**怎么用**:能写「主导」「负责」「Owner」就绝不写「参与」「协助」。一个项目如果不是你主控的,就降级合并到更高级的项目里,或干脆删除。

```
❌ 参与了 XX 系统的开发,协助完成了部分模块
✅ 【项目 Owner】0→1 搭建 XX 系统,主导整体架构与核心模块设计
```

**反模式**:把实习期间所有打杂小事列成 8 个「参与」条目——主动告诉 HR「我什么都没独立做成」。

### 军规 2 · 强调 0→1

**为什么**:`0→1` 是简历里含金量最高的三个字。从零搭建比「迭代维护」难一个量级,也是面试官最爱深挖的点。

**怎么用**:从零搭建的项目,第一个字就写 `0→1`。如果是迭代维护,诚实写「迭代」,但突出你在迭代里做的架构升级或性能提升。

```
❌ 负责维护公司内部的 XX 平台,处理日常需求
✅ 0→1 搭建 XX 平台;后续主导 1.0 → 2.0 架构升级,5 节点固定流水线 → 单 Lead Agent 统一调度
```

**反模式**:把维护写成 0→1。背调或深挖时一戳就穿,比不写更糟。

### 军规 3 · 外部认可替代自我评价

**为什么**:`学习能力强`、`认真负责` 是简历最没用的五个字——每个候选人都这么写,等于没写。面试官只信外部证据:开源 Star 数、排名、获奖、专利、公开发表。

**怎么用**:把所有自我评价词删干净,换成可验证的外部认可。

```
❌ 学习能力强,热爱技术,认真负责
✅ Apache Fory Committer · ByteDance/Deer-Flow Maintainer(★ 7.6k)
```

**反模式**:编造外部认可。背调期必挂,AI 时代 HR 验证开源贡献只需一次搜索。

### 军规 4 · 先抬项目再落自己

**为什么**:HR 平均看一份简历 15 秒。第一句话必须是「大场面」——项目多牛、平台多大、影响多广——然后才是「我」在里面做了什么。

**怎么用**:项目描述第一句写项目本身的江湖地位,第二句才写你的角色。

```
❌ 我负责开发了一个 AI Agent 项目,包含多个模块
✅ 字节排序第一的开源 Long-Horizon Agent Harness(★ 7.6k)——【项目 Owner】主导架构
```

**反模式**:通篇「我做了什么」,项目是什么读者要猜。

### 军规 5 · Before → After

**为什么**:人脑对「对比」最敏感。写出「改造前有多烂 → 我怎么改的 → 改完有多好」,比平铺直叙强十倍。也是面试官问「讲讲你最有成就感的项目」时的标准答案结构。

**怎么用**:每个大项目都用三段式:问题 → 方案 → 效果。

```
❌ 对系统进行了优化,提升了性能
✅ Before:五节点固定流水线,Sub-agent 频繁出错、重复执行
   After:单 Lead Agent 统一调度,Sub-agent 复用跳过 90% 并并行执行,测试集通过率 +25%
```

**反模式**:只写结果不写问题,或只写过程不写结果。

### 军规 6 · 数据说话

**为什么**:没有数字的简历是「文学」,有数字的简历是「证据」。百分比、耗时、数量、排名是 HR 和 ATS 系统共同识别的硬通货。

**怎么用**:每个项目至少 1 个量化指标。没有数据的,标 `【待补】` 向用户要,**绝不编造**。

```
❌ 大幅提升了系统性能
✅ 单任务耗时从 90s+ 压到 <20s,测试集通过率 +25%,生成时长降损约 30%
```

**反模式**:编数据。简历造假的代价是 offer 收回 + 行业拉黑。

### 军规 7 · 专业词汇密集

**为什么**:简历的第一读者有两个——ATS 关键词筛选系统和岗位 JD。你写的词和 JD 对不上,人再优秀也会被机器筛掉。

**怎么用**:先问目标岗位,再对着 `references/jd-keywords.md` 的关键词库,每个项目至少埋 3 个岗位词。

```
目标岗位:AI 应用工程师
关键词:Agent / LLM / RAG / Context Engineering / 评测 / Prompt / 微调
✅ 构建了 Agent 评测流水线,覆盖 SWE 系列 Benchmark,设计 Rubric Eval & Wash 管道
```

**反模式**:堆砌所有热门词但完全无关——「精通 Java、Python、Go、C++、React、Vue、MySQL、Redis」全家桶,HR 一眼看穿是凑数。

### 军规 8 · 分点清晰

**为什么**:一大段文字没人读。每个项目必须四段式切分:背景、职责、技术、数据。扫描式阅读的人只需 4 个关键词就能定位重点。

**怎么用**:严格遵守四段式模板,项目名 + 徽章开头。

```
项目【字节排序第一的开源 Long-Horizon Agent Harness】
─ 背景与目标:……
─ 我的职责:……
─ 技术细节:……(2-4 条)
─ 数据指标:……
```

**反模式**:一坨文字没有结构,把技术、职责、数据混在一起写。

### 军规 9 · 关键词加粗高亮

**为什么**:视觉引导。`0→1`、`Owner`、核心词、数据必须肉眼可见,让 HR 扫一眼就能抓住重点。

**怎么用**:关键内容用 `<span class="hl">` / `<span class="metric">` 加粗高亮,数据用徽章。

```
✅ <span class="hl">0→1</span> 搭建 · 通过率 <span class="metric">+25%</span> · <span class="badge">★ 7.6k</span>
```

**反模式**:全文加粗 = 全文不加粗。

### 军规 10 · 人设打造

**为什么**:简历是一张「标签页」。HR 第一眼必须看到你是谁、你的最高成就。

**怎么用**:头部 = 姓名 + 3 个以内头衔标签(最高那个给金色)+ 联系方式 + 最炸外部认可单独一行红条。

```
LoFiSu · Apache Fory Committer · ByteDance/Deer-Flow Maintainer
[⭐] 字节排序第一开源项目 Owner
```

**反模式**:头衔 8 个全堆上(含「学生会副主席」),等于没有头衔;最高成就藏在简历第二页。

### 军规之外的隐藏规则

- **一屏法则**:核心信息(头衔、最强项目、最炸认可)必须在一屏内被看到
- **针对岗位定制**:投递不同岗位,重排项目顺序和关键词
- **真实是底线**:措辞可以最锋利,事实必须最真实

## 二、GodSU 11 个手法(改写手法库)

> 手法层讲**做什么**,句式层讲**具体怎么写**(见 §三)。改写时逐条对照套用。

### 1. 头部信号压缩

前 5 行塞进所有最稀缺的信号,每个都带锚点:

```
20 years old · Full-Stack AI Agent Developer · Open to opportunities
github.com/xxxx(Apache 顶级项目 Committer｜某大厂头部开源 Agent 项目 Maintainer)
X 大学(中央部委院校)中外合办软件工程创新人才实验班 | 2023-2026(本科跳级毕业)
```

弱项也能通过加限定词变成信号(学校不顶尖 → 「中央部委院校」「合办实验班」「跳级毕业」三连)。

### 2. 极值标签

- 「18 岁成为**全球最年轻**的 Apache 项目 Committer」
- 「某大厂**排名第一**的开源 Long-Horizon Agent Harness 项目」
- 「开发**全球首个** Apple Vision Pro Agent」

极值词(最、第一、首个、唯一)制造记忆点。极值不成立时,**加限定词收窄范围直到成立**(「全球最年轻」→「国内最年轻」→「社区当年最年轻」)。

### 3. 借势(绑定大实体)

把自己绑到读者已知的大实体上:数万 stars 的开源项目、头部互联网大厂、一线 VC 被投企业、主流大模型厂商。

```
github.com/orgname/project ⭐️stars 76k · forks 10.3k
```

star 数直接写进标题行——让数字替自己说话。

### 4. Ownership 语言

每段职责的第一句几乎都是同一个句式:

```
我的职责:项目owner,完全负责从 0 到 1 设计并落地以下系统架构与技术链路
```

「owner / 核心作者之一 / 主导 1.0 到 2.0 的架构升级」。永远不出现「参与」「协助」「配合」。

### 5. 统一叙事骨架

每段经历都是:**背景与目标 → 我的职责 → 技术链路 → Benchmark 指标**。先立痛点再给目标,读者自动进入「看解决方案」的心态。

### 6. 演进叙事(展示判断力)

最强的一段是 `1.0 → 2.0` 的架构升级故事:

```
1.0 上下文压缩 / 沙箱 / 记忆逻辑散落各处,改一处要动多处;2.0 抽成 11 层有序流水线,新增或修改能力只动对应层,Agent 推理代码零改动
```

句式模板:**旧方案的具体痛点 → 我的改法 → 可感知的收益**。比任何功能列表都有说服力,因为它展示的是「为什么这么改」的判断力。

### 7. 热词命名

把自己做的工作命名成行业最前沿的术语,并组成体系:

```
Agent Teams Harness + Middleware Chain + Skill System + Context Engineering
```

对照映射表(用户真实能做清的才映射):

| 用户的原始描述 | 升级后的命名 |
|---|---|
| 上下文太长就截断/总结 | Context Engineering(Write/Select/Compress/Isolate 四分法) |
| 用 GPT 给输出打分 | LLM-as-Judge 评估引擎 |
| 找出 agent 从哪一步开始出错 | Failure Onset 定位 |
| 跑一下测试看 patch 过不过 | Test-in-Loop |

**风险提示**:每个热词都是面试官的必问点,用户讲不清就是自爆。

### 8. 细节密度压制

写到参数级,密到面试官没法逐条质疑:

```
调度与执行双线程池分离,最多 3 并发 / 单任务超时 900s
超 180k 触发 Micro compact,超 250k 触发 LLM 兜底
规则压缩历史为 ~12k 结构化文本
```

具体数字 = 可信度。一条 bullet 里有三四个具体参数时,读者会默认作者对系统了如指掌。

### 9. 量化留余地

```
通过率较全量重跑提升约 25%+,单任务推理成本降低约 30%+
付费转化率约 38%;月活 500+
```

全是「约 / + / 区间」。比精确数字更可信(真实世界的数字就是毛的),更难被当场证伪。每个数字的**口径**(怎么测的、baseline 是什么)用户必须能一句话说清。

### 10. 社会证明侧写

不直接夸自己强,而是罗列「被系统认可」的记录:

```
荣登某大厂内部技术社区首页文章周榜 13 次,作者等级 LV8,2025 年该厂优秀技术创作者榜第 13 名
帮多家一线 VC 被投 AI Startup 实现 Agent 业务落地
```

内部榜单、等级体系、比赛名次、合作名单——第三方背书永远强于自我描述。挖料时专门问:有没有任何「上过榜/得过奖/被引用/被采纳」的记录。

### 11. 人味尾巴

```
高中时期做过 Live2D/3D 数字人,二次元平台产品经理,对二次元文化有深入了解。
```

结尾留一个反差记忆钩子。面试官记不住 20 条 bullet,但会记住「那个高中做数字人的」。

## 三、GodSU 13 个句式(可复用零件)

> 改写时逐条对照套用。模板里 `(占位符)` 表示需要替换的内容。

### 1. 三段式定位句

```
> 20 years old · Full-Stack AI Agent Developer · Open to opportunities
```

**模板**:`稀缺属性 · 身份定位 · 状态`。用 `·` 分隔,英文定位词比中文职位名更有「个人品牌」感。身份定位选行业当前最热的角色名(Full-Stack AI Agent Developer,而不是「软件工程师」)。

### 2. 括号补刀

```
> X 大学(中央部委院校)中外合办软件工程创新人才实验班 | 2023-2026(本科跳级毕业)
```

**模板**:`主体(拔高限定词)`。括号是简历里最便宜的信号放大器。一个弱项配 2-3 个限定词就能翻转成信号。

### 3. 身份即链接

```
> github.com/xxxx(Apache 顶级项目 Committer｜某大厂头部开源 Agent 项目 Maintainer)
```

**模板**:`可点击锚点(身份标签1｜身份标签2)`。锚点在前身份在后。

### 4. 痛点—目标句(背景段)

```
> 单一模型轨迹风格单一易过拟合——借鉴「Mix Diverse GPTs」,引入多种 scaffold 提供风格不同的轨迹……目标:规模化合成覆盖多 scaffold 的高质量多样化轨迹
```

**模板**:`痛点陈述——借鉴「权威方法论」,做法;目标:一句话目标`。两个部件:破折号引出解法制造「问题→洞察」的节奏;「引用体」给自己的做法找到学术/行业出处。

### 5. 职责定位句(每段第一句)

```
> 我的职责:项目owner,完全负责从 0 到 1 设计并落地以下系统架构与技术链路(CLI:relay run → export)
```

**模板**:`我的职责:角色定位,完全负责从 X 到 Y + 交付物类型(具象锚点)`。结尾的括号锚点(一条 CLI 命令、一个入口 URL)是点睛之笔——用具体到能敲进终端的细节,为整段的宏大陈述作担保。

### 6. 新旧对比句(演进叙事)

```
> 1.0 上下文压缩 / 沙箱 / 记忆逻辑散落各处,改一处要动多处;2.0 抽成 11 层有序流水线,新增或修改能力只动对应层,Agent 推理代码零改动
```

**模板**:`旧版本 + 具体病症;新版本 + 我的改法,可感知的收益`。收益要写成「零改动」「只动对应层」这种绝对化但可验证的表述,比「大幅提升可维护性」强一个数量级。

### 7. 箭头链路句

```
> Coordinator(意图识别)→ Planner → Research Team(Researcher / Coder 支持 MCP 动态扩展外部工具)→ Reporter(汇总上下文生成最终报告)
```

**模板**:`节点(职能)→ 节点 → 节点(补充说明)`。把流程压进一行箭头链,读者 3 秒看懂体系全貌,同时暗示「这个体系是我设计的所以我能一笔画出来」。

### 8. 命名枚举体系(自造概念)

```
> Write——中间结果写入文件系统…;Select——按 token 预算…裁剪注入记忆…;Compress——超限调轻量 LLM 压缩历史…;Isolate——Sub-agent 仅见任务描述…
```

**模板**:`动词1——做法;动词2——做法;…`(3-4 个一组)。把散落的工作归纳成一套有命名的方法论,是「执行者→设计者」的语言升维。命名尽量对齐行业已有提法(这四个词来自 LangChain 的 context engineering 四分法),面试官认出出处反而加分。

### 9. 现象命名句(诊断力展示)

```
> Agent 失败根因是能定位相关代码证据但无法正确解读并转化为行动(Evidence-to-Action Gap)
```

**模板**:`对现象的白话诊断(English-Named-Gap)`。给自己发现的问题起一个英文术语名。这是全份简历里最「论文感」的话术——暗示这个洞察值得被命名,而命名权在我。

### 10. 指标冠名句

```
> Benchmark 指标:SWE-Bench 系列难题通过率较全量重跑提升约 25%+,单任务推理成本(API 与时长)降低约 30%+
```

**模板**:`Benchmark 指标:指标名较基线提升约 X%+,成本指标(口径注明)降低约 Y%+`。三个部件:① 冠以「Benchmark 指标」标签;② 永远写明**对照基线**;③「约 X%+」的模糊精确体。

### 11. 荣誉数字化罗列

```
> 荣登某大厂内部技术社区首页文章周榜 13 次,作者等级 LV8,2025 年该厂优秀技术创作者榜第 13 名
```

**模板**:`平台 + 榜单/等级 + 次数/名次`,连排 3 个以上。单个荣誉是点,连排就是「持续被认可」的证据链。名次不高也照写(第13名)——有名次本身就是信号。

### 12. 朋友圈句(关系借势)

```
> 帮多家一线 VC 被投 AI Startup 实现 Agent 业务落地;与国内主流大模型厂商 A、B、C、D……深度合作
```

**模板**:`帮/与 + 大牌名单(4 个起排,"等"结尾)+ 动词短语`。名单必须真实;动词选「合作/落地/参与评测」这类可宽可窄的词,为真实性留缓冲。

### 13. 反差尾巴句

```
> 高中时期做过 Live2D/3D 数字人,二次元平台产品经理,对二次元文化有深入了解。
```

**模板**:`非常规时期/场景 + 做过的具体事 + 一句身份或态度`。整份简历唯一一句「不像简历」的话,放最后。

## 四、句式通用规则

1. **绝对化收益 + 模糊化数字**:定性收益敢写死(「零改动」「提前退出」),定量数字要留缓冲(「约 25%+」)。方向相反的写法(定性含糊、数字精确到小数点)是业余信号。
2. **每个宏大陈述配一个微观锚点**:说「完全负责系统架构」就附一条 CLI 命令;说「开源核心作者」就附 GitHub 链接。宏观负责叙事,微观负责可信。
3. **动词降权表**:参与 → 主导;协助 → 负责;使用 → 设计并落地;优化 → 重构/改造;了解 → 深度参与。**前提:升级后的动词必须与真实角色相符**(防伪审计把关)。
4. **热词必须能定义**:每个从这里套用的术语,用户都要能口头给出一句话定义 + 一个自己工作里的实例。做不到就用平实说法——话术的上限是真实度。

## 五、典型改写前后对比(摘要)

完整案例见 `examples/baseline-vs-sushen.md`。摘要:

| 维度 | 普通写法 | 酥神写法 |
|------|---------|---------|
| 动词 | 参与了 / 协助了 / 学习了 | 【项目 Owner】/ 主导 / 0→1 搭建 |
| 项目开头 | 「我负责开发了 XX」 | 「字节排序第一的开源 XX(★ 7.6k)」 |
| 数据 | 「大幅提升性能」 | 「单任务耗时 90s+ → <20s,通过率 +25%」 |
| 自我评价 | 「学习能力强,认真负责」 | 「Apache Fory Committer · Deer-Flow Maintainer」 |
| 结尾 | 「可随时到岗」 | (删掉,用数据证明) |

> 一句话:把「我做了什么」翻译成「我搭了什么、改了什么、涨了多少」。
